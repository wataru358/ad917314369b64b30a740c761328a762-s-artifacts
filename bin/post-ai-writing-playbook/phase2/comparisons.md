# Phase 2の収録、比較、判定を実装する

## 入力を照合する

R01の `phase2-inputs.json` にある相対パスとハッシュを検証する。T01の `cohort.csv`、T02の `articles.jsonl`、`metadata.csv`、`segmentation.py`、`fixtures.json`、`topic-map.json`、T00の `extract.py`、T01の `language-rules.py` と `language-settings.json` がこの分岐の入口になる。旧資料がSQLiteの場合は `prose_units`、`owners`、`sentences`、`tokens` を同じ意味の中間行へ対応させる。R01の元runとID領域を記録する。

D03の `plan.jsonl` と `responses.jsonl` を計画順で照合する。1始まりの `position`、数値DEV `id`、UTCの `month` と `published_at`、取得状態、原応答・本文のハッシュを保持する。原応答にある公開時刻とplanを照合し、記録済みのAPI Markdown・HTMLを取り出す。元の新収録は各月1,000件、全10,000件で、固定planの穴を別IDで埋めなかった。

旧の採否と用意した抽出器を固定する。新ではHTMLの構造が読める本文を使い、API本文断片を旧抽出器の本文ルートに適応させる。抽出本文の順序、元HTMLまでのoffset・DOM path、P/L/U、見出し、太字区間、警告を保存する。Markdownの有無を記録する。固定仕様ではHTMLが空でもMarkdownを代用しない。保存Sがない場合は理由を付け、本文に存在しなかった散文を補わない。

## 新集合の採否を固定する

Sとして保存した全文を英語、非英語、実質的な混在、不明、本文なし、取得不能へ分ける。英語の対象は保存されたSであり、記事の品質や技術性と独立。外国語の固有名や借用語だけで混在とはしない。書き手が外国語で読者へ説明や指示をしているか、出典・引用・作品名・技術用語だけかを文脈で確かめる。

旧規則の機械補助はLingua 2.1.1、75言語、最高スコア0.7、次点との差0.3、最低語数なし。R01の索引が指す旧言語規則を使い、S、P、L、Sの1,200文字区間を照合する。出力は内容採否の補助とする。全件を計画順に処理し、同じscopeの既検証pilot行があればハッシュを確かめて再利用する。残りは最大25件ずつに区切る。本文のラベルと根拠を先に保存して封印し、その後に対応する機械出力を開いて照合する。自動英語も全文を確認する。機械結果が欠けた場合は照合不能の理由を残す。実施していない判定を本文ラベルとして記録しない。

採否コードは `accept_english`、`exclude_non_english`、`hold_mixed`、`hold_unknown`、`no_prose`、`unavailable`。英語採用だけの抽出を採否台帳の完全な部分集合にする。訂正は元ラベル・本文・照合ファイルのハッシュと行を参照し、開示後なら `scores_already_seen=true` と記録する。元判断を保持する。元runの採否件数は英語8,942、非英語662、混在151、不明69、本文なし101、取得不能75。7訂正は元runの来歴であり、新規runは観察した訂正だけを残す。

## 支持と感度の出力をそろえる

記事キーは `cc:<source_article_id>` または `api:<source_article_id>`。著者の既知の数値IDは経路共通の `dev:user:<numeric_id>`。著者D/Hは完全同文を橋とする既知著者の連結成分ごとに割り当てる。発見・確認の標本ごとに、全記事、有効記事、著者、月、失敗原因を残す。語彙、X01、X03の未知著者の出力は別の探索とし、主基本指標に使うbootstrap仮キーを実著者として数えない。

基本Mは `main`、2019〜2022年の比較、記事単純平均、著者平均、既知著者のみ、AIタグ除外、話題標準化、完全同文と近似同文の重み、P+L長さ層、M04のlog1pを区別する。C01は元尺度の4年外挿、固定感度、backtestを別に保存する。語彙の9条件は [追加集計の手順](supplements.md) と同じ名前を使う。条件ごとに各月の採用数・有効数・分母・除外質量・共通支持を添える。話題に支持がない月はNA。記事を限定する感度の差を、因果的な説明割合へ変換しない。

比較行のキーは `family,id,variant`。V01とV02の行は同じ語でも別キーで全件保持する。BHは `term` の同じ仮説を1回だけ補正し、両行へ同じ補正値を返す。固定5系列のV03とdelveの4語形補助を別にする。各行に `estimate`、支持、区間、有効反復、NA理由、入力IDと元出力の行番号を持たせる。F/R/A、実著者数、最大著者占有率は別項目。倍率分母0はnullと生件数。本文一致数、使用記事・著者率、推測の区間を混同しない。

## X02と自動定義を独立に確認する

X02の校正200枠と確認900枠を、固定saltと著者・年月で先に割り付ける。確認Hは旧各年・月12著者枠と新各月30著者枠から1記事ずつ選ぶ。未充足枠を明記する。別標本の自動定義の校正はD各経路50件、確認はH各経路100件。X02標本を除外する。Dの校正候補からS02の言語確認標本を除き、Hの確認で以前の言語確認が当たった場合はその履歴を記す。X02の著者順位は `SHA256(x02_salt + YYYY-MM + ":" + author_key)`、著者内は `SHA256(x02_salt + YYYY-MM + ":" + article_key)`。自動定義は `SHA256(validation_salt + article_key)` 順。blind IDはX02で `SHA256(x02_salt + "blind:" + article_key)`、自動定義で `SHA256(validation_salt + ":blind:" + article_key)` の先頭24桁。UTF-8で連結し、hexを使う。衝突を検査する。開始前に標本IDとblind ID対応表を封印する。

判定入力は匿名ID、P/Lのownerと文・fragment、必要な範囲・語位置だけ。時期・経路・著者・URL・語彙結果・既存自動値・もう一方の判定を担当に渡さない。原HTML証拠を使う確認では、確認対象の根拠だけを提示し、伏字と残る手掛かりを記録する。本文から年代を推測できる可能性は残る。別contextの独立した2系統のAIが、原文を読み、文ごとのE/Gのpositive、negative、unknown、根拠spanを明示する。短い抜粋だけで全文の判定を代用しない。各判定系統の原回答と理由、要求モデル・推論設定・起動結果、packetとschemaのハッシュを保存する。取れない実測モデルや実行量は理由付きnull。判定担当はAIとして記録する。

陽性は `owner_id,start,end,quote` を必須とし、元のUnicode code point位置と一致させる。手数えは分子・分母と根拠を自動値に触れる前に封印する。集約器は全行と両系統の来歴を検証し、同じラベルだけ採用する。不一致・判断不能はunknown。X02の各ラベルの記事有無の一致率・κは両系統の有効な組で計算し、除外組も数える。固定0.80/0.60を満たすかを記録する。一致は外部正解率とは別である。語率の点、下限、上限は [固定測定仕様](measurement-spec.md) のword位置のunionを使う。差のunknown範囲は新下限−旧上限から新上限−旧下限まで。これは95%区間と別に表示する。

自動定義の確認ではsegmentation、bold、V03、X01、X03、表示エラー、広告、署名を分ける。Mの手数え差、太字の原DOM根拠、明示した合議参照、正と負の実数を残す。自動定義の検証用で合議参照が得られなければ独立ラベルの一致だけを示し、内容精度の判定を保留する。V03、X01、X03の二値精度は合議参照の正・負各20件以上でprecision/recall各0.90が基準。品質フラグは固定標本内の探索であり、全量classifierを置かない。品質によるM感度はbaseline、表示エラー、広告、署名の4条件×6指標。支持不足の比較も24行全部を残す。

## 保存値を検証してから主張する

S04で固定データの全キーを列挙し、独立計算で算術、分母、区間、補正、支持、NAを確かめる。先に合成小例、次に固定した実物の中間値・集計値を照合する。S05は保存出力から既存検算との同一性を確認し、測定妥当性、固定感度、交絡を各主張へ対応させる。元のrunでは2,897の比較行を網羅し、8,450行の感度対応を保存した。行数は新runのinventoryから確認する。

判断単位はM01〜M06、V01、V02、V03の5系列、X01、X02-E、X02-G、X03、C01の18個。C01の判断から6指標の値・backtestへ戻れるようにする。各行は限定採用、保留、判断不能のいずれかとし、計算、測定、支持、頑健性、代替説明、許容される文、根拠の位置を付ける。区間が0を含むだけで「変化なし」とは結論しない。根拠が足りない判断は理由を読めるようにして工程を閉じる。

元runでは、分割200記事の未解決、手数え差38件、太字の原文証拠不足200記事、合議参照0件が残った。V02の8候補はHの条件を満たさず、X02-Eの語率区間は有効反復4,342でNA、X02-Gの語率は必要月欠けでNAだった。V03の `worth` は区間が0を含み、`delve` は末尾200語で点差の向きが変わった。新runの照合では同じ問題があれば根拠とともに記録する。
