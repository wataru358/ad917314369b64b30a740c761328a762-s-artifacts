# DEV記事の取得を進める

この工程の担当は、Common Crawl に保存された DEV のページと、DEV API が返す2026年の記事を、再検証できる形で残す。親の `AGENT.md` と `config.json` を読み、`python3 workflow.py next` で再開位置を確認する。

| タスク | 入力 | 渡すもの |
| --- | --- | --- |
| [D01](cc-index/AGENT.md) | `CC-MAIN-2025-43` の公開索引 | 固定した候補パスと索引ファイル一覧 |
| [D02](cc-html/AGENT.md) | D01の確定成果物 | 圧縮WARC、HTML、全候補の取得台帳 |
| [D03](dev-api-2026/AGENT.md) | DEV API の一覧と個別応答 | UTC各月の固定計画、原JSON、取得台帳 |

D01とD03は依存関係がなく、タスクごとに出力先を分けて進められる。D02の入力は、同じ `run_id` でD01が確定した成果物とする。全タスクとも `workflow.py start` が返す `runs/<run_id>/download/<task-id>/<attempt>/` に出力する。後工程は完了した試行の `output_dir` を状態から解決する。

初回は [取得仕様](download-spec.md) の共通条件と担当節を読む。全量取得に先立って、5件で仕様と保存形式を確かめる。D01は索引の5候補行、D02は固定候補の5レコード、D03は接続確認の一覧にある5件と固定計画の先頭5件を使う。上限や待機で区切った後は保存済みの位置から続ける。サーバーの待機期限を優先し、待機中は依存しないタスクを進める。

5件の検証は完了レシートを発行する前の確認とする。全量の完了条件を満たしてから成果物を渡す。英語判定、本文抽出、分析の採否は後工程で行う。

引き継ぐときは [ダウンロードの引継ぎ](download-handoff.md) を使う。歴史上の件数と参照元は [元の調査資料](provenance.md) にある。
